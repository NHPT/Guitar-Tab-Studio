# Guitar Tab Studio 社区标注与开放训练路线图

## 1. 目标与原则

Guitar Tab Studio 要把长期依赖单人复核和训练的流程，升级为所有注册用户都能参与、
结果可审计、模型可复现的社区机器学习系统。

“所有人都可以参与”具体指：

- 普通用户无需乐理背景，也能完成试听质量、起音存在、漏音、误报和时间边界任务。
- 通过校准的用户可以继续处理音高、弦品和基础技法。
- 所有通过账号与资源校验的用户都可以提交受控训练实验。
- 贡献者可以查看自己的贡献、公开验证结果和模型卡。

“所有人都可以参与”不表示任何人都能直接修改原始贡献、读取隐藏测试集、执行任意
训练代码或绕过门禁切换生产。当前单人维护阶段允许项目所有者承担最终发布职责；
多人维护后再启用强制职责分离。

核心原则：

1. **小任务优先**：将完整歌曲复核拆成数秒级、单问题任务。
2. **不确定可以跳过**：不强迫用户猜测同音异弦或复杂技法。
3. **渐进式治理**：单人阶段保留完整审计和自动门禁，不虚构第二审批人；团队阶段
   再强制提交与批准分离。
4. **原始贡献不可变**：修订通过追加版本表达，不覆盖历史。
5. **数据与模型全链路追溯**：训练结果必须绑定数据、代码、配置、环境和评测哈希。
6. **公开验证与隐藏晋级分离**：公开指标用于迭代，隐藏指标决定能否进入生产。
7. **权利先于技术价值**：没有明确训练与再分发权利的数据不进入社区任务池。

## 2. 借鉴的成熟实践

| 来源 | 可采用机制 | Guitar Tab Studio 调整 |
| --- | --- | --- |
| Mozilla Common Voice | 社区贡献与他人验证分离，允许跳过不确定样本，记录来源与许可。 | 将语音片段验证改为起音、漏音、时间边界等吉他微任务。 |
| Zooniverse | 一个样本由多名志愿者独立处理，达到分类数后退休；专家提供金标准任务。 | 对困难片段使用盲双审或盲三审，达到共识后停止继续分发。 |
| Label Studio | 标注者、复核者角色分离，使用重叠标注、一致率、低信任保护和质量看板。 | 保留现有音频/TAB 专用界面，只借鉴其权限和质检机制。 |
| DVC | 用可读元数据和内容哈希版本化数据、参数、流水线与制品。 | 音频放对象存储，仓库只保存版本化清单、哈希和流水线定义。 |
| MLflow Model Registry | 跟踪实验来源、模型版本、标签、别名和回滚关系。 | 统一管理 `candidate`、`shadow`、`champion` 和 `retired` 模型。 |
| Hugging Face Cards | 数据卡、模型卡披露来源、许可、用途、限制、训练参数和评测结果。 | 每个数据快照和候选模型自动生成卡片，不以单一总分替代分域指标。 |
| Kaggle | 公开榜用于开发，隐藏榜决定最终排名，减少针对评测集过拟合。 | 社区只看到公开验证结果；全新密封盲测仅由晋级服务按配额执行。 |

这些机制是设计依据，不代表必须引入对应产品。标注界面继续使用现有工作台，
数据版本和模型注册优先选择开源、自托管组件。

## 3. 参与者与权限

权限按任务类型授予，而不是给账号一个永久、全局的“专家分数”。

| 角色 | 获得方式 | 可以做 | 不可以做 |
| --- | --- | --- | --- |
| 注册贡献者 | 完成账号验证与简短教程 | 提交个人纠错；处理音质、漏音、误报、起音任务 | 查看他人答案；批准金标准 |
| 校准标注者 | 通过该任务类型的隐藏金题 | 处理已解锁的音高、弦品或技法任务 | 处理未通过校准的任务类型 |
| 可信复核员 | 持续达到质量和数量门槛 | 复核低一致率任务；给出退回原因 | 复核自己的提交 |
| 金题作者 | 经人工授权并保留资质记录 | 起草金题和判定依据 | 修改原始贡献 |
| 专家裁决员 | 经人工授权并通过领域校准 | 裁决争议和复核金题 | 修改原始贡献 |
| 数据发布者 | 当前为项目所有者，后续可授权 | 核验共识、裁决和证据链后冻结数据版本 | 跳过自动校验；修改原始贡献 |
| 实验贡献者 | 注册用户接受实验规则并通过资源校验 | 选择数据版本和批准的训练配方，提交实验 | 读取隐藏测试；运行任意代码；部署模型 |
| 模型维护者 | 当前为项目所有者，后续可授权 | 复现、提名、批准或回滚生产模型 | 绕过自动门禁 |
| 治理管理员 | 当前为项目所有者，后续可授权 | 授予或撤销角色；处理权利与安全事件 | 绕过审计或自动门禁 |

新用户从基础任务开始。弦品与技法权限分别解锁，避免“懂节奏但不懂指板”或
“会弹琴但不熟悉某类技法”的用户被错误地视为全领域专家。

### 3.1 单人阶段与团队阶段

当前采用**单人维护模式**：

- 社区成员独立提交，系统形成共识；项目所有者只处理争议、抽检并冻结数据版本。
- 项目所有者可以同时担任数据发布者、模型维护者和治理管理员，不需要等待第二名
  发布者，因此不会阻塞开发或发布。
- 单人确认的数据记为 `owner_verified`，可以进入训练版本，但必须公开标明尚未经过
  独立专家复核，不能充当最终密封评测真值。
- 模型通过全部自动门禁、密封评测、影子和灰度后，可由项目所有者批准；模型卡记录
  `approval_mode=single-maintainer`。

当出现第二名稳定维护者后切换为**团队治理模式**：

- 标签作者不得裁决自己的标签，模型提交者不得独自批准自己的候选。
- 金标准冻结、生产晋级和高权限授予采用一人发起、一人批准。
- 紧急回退仍允许一人执行，事后由另一名维护者复核。

“双人发布”指未来团队阶段对关键发布执行四眼原则，不是要求两名社区标注者共同点击
发布，也不是当前阶段的前置条件。

## 4. 标注任务拆分

### 4.1 无需乐理的基础任务

每次只展示一个问题和一个可循环播放的短片段：

- 音频是否清晰、是否对齐、是否包含目标乐器。
- 指定位置是否有新的触弦起音。
- 模型事件是正确、误报还是无法判断。
- 片段中是否还有未标出的音。
- 起音或结束边界是否需要前移、后移。

普通用户不需要填写 MIDI、弦号、品位或技法。界面必须提供“无法判断”和“跳过”，
跳过不降低信誉。

### 4.2 需要校准的音乐任务

- 音高或音名确认。
- 物理弦与绝对品位确认。
- 和弦或同起音音组确认。
- 推弦、击弦、勾弦、滑弦、泛音、闷音等技法确认。
- 变调夹、特殊调弦和演奏上下文确认。

同音异弦无法从音频可靠区分时，必须保留“音高已确认、弦品未知”，不能猜测。
推弦记录起始品位和 `bend` 技法，不用目标音高改写起始品位。

### 4.3 任务生成

任务来源按优先级分为：

1. 模型低置信度、模型间分歧和候选缺失。
2. 当前门禁失败最多的 residual 起音、快速同弦重复音和分轨泄漏片段。
3. 类别、演奏者、琴型、录音设备和音色覆盖缺口。
4. 随机审计样本，防止主动学习只覆盖模型已知盲区。

任务快照创建后固定音频哈希、时间窗、模型版本、预填结果和问题版本。指南或模型
更新不会静默改变已分发任务。

## 5. 数据状态与隔离

```text
private_correction
       |
       | user consent + rights check
       v
quarantined -> rejected / withdrawn
       |
       | immutable task snapshot
       v
blind_review -> consensus -> owner review -> owner_verified
                     |                              |
                     | optional independent review  v
                     v                    frozen_dataset_release
               gold_candidate                      |
                     |                              v
                     v                  approved training recipes
              adjudicated_gold

sealed_evaluation ---------------------------------> promotion gate only
```

### 5.1 数据层

- `private_correction`：用户自己的项目修订，默认仅本人可见，不用于训练。
- `quarantined`：用户明确授权后的候选数据，等待权利、格式、安全和重复性检查。
- `blind_review`：已分发但未形成共识的不可变任务。
- `consensus`：达到多人一致标准，可用于研究训练，但不能作为锁定评测真值。
- `owner_verified`：社区共识经过项目所有者抽检或争议处理后冻结的训练标签；当前
  单人阶段可使用，但不能作为最终密封评测真值。
- `adjudicated_gold`：经过独立专家裁决的标签；团队阶段由第二名维护者批准发布。
- `frozen_dataset_release`：固定清单、切分、许可证、哈希和数据卡的训练版本。
- `sealed_evaluation`：与训练和公开验证物理隔离，只能由晋级服务读取。

社区 schema 必须分别记录 `performer_id`、`work_id`、`recording_id`、
`session_id` 和 `lineage_id`。切分器按这些关系及音频指纹形成连通分量后分组，不能
只选择演奏者或歌曲其中一个维度。一个来源的不同分轨、片段、增强版本和转码版本必须
留在同一分区。现有 schema v1 的 `group_id` 继续兼容读取，但新数据必须使用能同时
覆盖演奏者、作品和派生链的保守分组。

数据用途必须保持互斥：

| 数据用途 | 可用于贡献者校准 | 可用于训练 | 可用于模型评测 |
| --- | --- | --- | --- |
| 隐藏金题 | 是，任务身份对用户隐藏 | 可以，纳入训练版时需去除金题标记 | 否 |
| 社区共识与裁决数据 | 否 | 是 | 仅公开开发验证，不得作为锁定门禁 |
| 来源谱真实评测事件 | 否 | 否 | 是 |
| 最终不少于 100 首盲测集 | 否 | 否 | 是，且只进入 `sealed_evaluation` |

现有 246 个真实评测事件和后续追加的 200 个来源谱事件不得转作社区金题。C1 的
至少 300 个校准事件来自 residual 训练审核材料，与模型评测集不重叠。

### 5.2 音频权利边界

- 公开社区任务池只接收允许训练且允许向复核者分发的自有、授权或兼容许可数据。
- 用户上传的商业歌曲默认只能用于个人推理和私有纠错，不能因用户点击“贡献”就
  自动获得再分发或训练权。
- 每个音频对象记录来源、权利依据、许可版本、允许用途、保留期限和撤回状态。
- 撤回后立即停止新任务分发并从后续数据版本排除；已发布模型的影响在数据卡中记录，
  按删除策略安排重训，不能承诺无法验证的即时机器遗忘。

可接受的权利证据只包括可核验的数据集许可证与版本、自有录音的贡献者声明，或权利人
明确授权。来源或授权不可核验时直接拒绝。已批准的公开数据集可自动校验许可证清单；
自有录音和单独授权由治理管理员复核。C0 必须在 C2 前冻结保留期限、撤回处理时限、
重训触发条件和申诉流程。

调度器每次运行前查询全局撤回清单。任何包含已撤回对象的历史数据版本立即标记为
`blocked`，不能启动新训练；待运行任务取消，未发布的片段、波形、特征、缓存和金题
副本按删除策略清除。不可变审计记录只保留不含个人内容的 tombstone、哈希、时间和
处置结果。已运行实验与已发布模型不伪造“未使用”状态，而是记录影响范围并按策略触发
重训、撤回或风险接受。

## 6. 共识与质量控制

### 6.1 初始共识规则

规则上线前用专家金题校准，以下数值是首轮默认值：

| 标签类型 | 首轮分发 | 自动形成共识 | 升级条件 |
| --- | --- | --- | --- |
| 音质、事件存在、误报、漏音 | 2 人盲审 | 2 人一致 | 不一致时发第 3 人；仍无多数则复核 |
| 起音时间 | 2 人盲审 | 中位数差不超过 30 ms | 超差后第 3 人或专家 |
| 结束时间 | 2 人盲审 | 差不超过 50 ms 或音长的 10% | 超差后第 3 人或专家 |
| 音高 | 2 名已校准用户 | MIDI 完全一致 | 不一致或双方低置信时复核 |
| 弦品 | 3 名已校准用户 | 物理弦和绝对品位一致 | 同音异弦或无证据时标未知 |
| 技法 | 3 名对应类别已校准用户 | 类别与关联事件一致 | 长尾或冲突直接专家裁决 |

所有人看不到前序标注者身份和答案。模型预填可能造成共同偏差，因此至少保留一部分
无预填对照任务，并分别统计“看过预填”和“未看预填”的一致率。

### 6.2 信誉与审计

- 信誉按任务类型分别计算，依据隐藏金题准确率、与最终裁决的一致率和异常行为。
- 新用户处于成熟期，其结果参与评估但不单独形成自动共识；累计足够金题后才启用
  有限权重，单人或单个账号关联簇不能决定共识。
- 调度器不得把同一任务分配给同一账号关联簇内的多个成员；设备、身份、付款和行为
  关联只用于反滥用，不写入公开数据。
- 系统持续混入金题，但不向用户标记哪些任务是金题；金题设置曝光预算、轮换和退役。
- 每批自动共识结果抽样复核；错误率超门槛时暂停该任务模板和相关账号的自动计权。
- 检测极短作答、批量相同答案、账号协同、重复设备和异常时间分布。
- 信誉下降先限制高难任务，不删除历史记录，也不公开羞辱性排名。

### 6.3 质量指标

- 基础事件判断相对金题 F1 不低于 `0.90`。
- 起音在 `±50 ms` 下 F1 不低于 `0.95`，绝对误差中位数不高于 `20 ms`。
- 已解锁弦品任务的联合准确率不低于 `0.90`。
- 自动共识样本的专家抽检错误率不高于 `2%`。
- 数据来源、许可、同意版本和内容哈希完整率必须为 `100%`。
- 任何任务类型未达到门槛时，只能保留为研究标注，不能进入金标准。

指标按演奏者、音频条件、难度、设备和任务类型分层报告，不能只报告总体均值。C0
必须为每类任务冻结样本单位、正负类定义、每类最小支持数和 macro/micro 口径。
F1 报告分组 bootstrap `95%` 置信区间；`2%` 抽检错误率使用 Wilson `95%`
置信上界判定，不使用点估计。C2 的 `500` 个重叠判断是流量下限，不替代这些统计条件。

## 7. 人人可参与的训练方式

### 7.1 第一阶段只开放批准配方

实验贡献者通过表单选择：

- 已冻结的数据版本。
- 已批准的模型族，例如 residual onset 前端、CRNN 或 Conformer 基线。
- 受限范围内的学习率、损失权重、采样策略、种子和训练轮数。
- 公开验证指标和资源上限。

系统生成不可变实验定义并排队执行。第一阶段不接收任意 Python、Notebook、镜像、
依赖包或 shell 命令，避免代码执行、数据外传和供应链风险。

### 7.2 训练沙箱

- 训练任务必须在 rootless 强隔离运行时或微型虚拟机中执行，强制无外网、无宿主机
  路径、容器 socket、云元数据、长期凭据、Linux capabilities 和未批准设备。
- 数据集只读挂载，输出写入独立临时卷。
- 限制 CPU、GPU、内存、磁盘、时长、并发和每日配额。
- 训练节点、服务身份和生产节点隔离；镜像、依赖锁文件、入口命令和训练配方均由
  维护者签名。
- 失败任务自动清理，日志过滤物理路径、令牌、音频 URL 和个人信息。
- 输出只能通过服务端固定格式网关发布模型、指标和白名单报告；用户只能下载许可
  允许公开的制品，不能借日志、权重或自定义文件导出受限音频。

后续若开放自定义代码，必须经过代码审查、依赖锁定、镜像构建、恶意行为扫描和更
严格的独立队列；它不是社区训练的首发能力。

### 7.3 实验可复现包

每次运行必须生成：

- 实验 ID、提交者别名和时间。
- Git commit、训练入口和容器镜像摘要。
- 数据集版本、清单哈希和切分哈希。
- 完整参数、随机种子、依赖锁文件和硬件类型。
- 检查点哈希、公开验证报告、错误分类和资源消耗。
- 自动生成的模型卡，包含用途、限制、许可和不支持场景。

DVC 管理数据清单与流水线版本，MLflow 管理实验和模型注册。对象存储保存音频、
特征与权重，Git 不直接存放大文件。

## 8. 模型晋级与生产隔离

```text
community experiment
        |
        v
public validation leaderboard
        |
        | rate-limited nomination
        v
clean-room reproduction
        |
        v
sealed evaluation + robustness + security
        |
        v
shadow -> canary -> champion
                   |
                   v
                rollback
```

晋级分为“候选解锁”和“最终生产”两层。

候选只有在公开验证中满足 TAB F1 不回退、重复起音召回相对稳定训练基线至少提升
`0.01`，并通过各分域无回退检查后，才能申请一次受配额限制的密封评测。这个条件
只决定是否允许继续评测，不代表达到生产质量。

最终生产晋级依次通过：

1. **完整性门禁**：数据、代码、配置、环境和制品哈希齐全，许可证兼容。
2. **可复现门禁**：由平台在干净环境自动重跑，指标在确定性容差内一致；团队阶段
   再由未参与该配方、镜像或实验提交的维护者复核。
3. **公开验证门禁**：相对当前基线有统计意义的提升，不以单条歌曲决定。
4. **隐藏评测门禁**：贡献者不能读取样本、标签或逐条错误，只返回受限汇总。
5. **稳健与性能门禁**：分域回归、校准、推理时延、内存和异常输入通过。
6. **影子与灰度门禁**：不影响用户结果地观察，再小流量启用。
7. **人工批准**：单人阶段由项目所有者确认并记录
   `approval_mode=single-maintainer`；团队阶段由第二名模型维护者独立批准。

最终指标以 `model-training.md` 的 Production gate v2 为唯一权威策略，所有条件
按逻辑与执行：TAB F1 不低于 `0.75`、
相对 Basic Pitch 提升不低于 `0.15`、重复起音召回不低于 `0.85`，并满足真实来源
多样性与错误复核要求。技法模型还必须执行技法路线图 T6 的分域门禁；达到前相关
输出继续标记为实验性。`champion` 只指向已通过全部门禁的模型，旧版本保留一键
回滚。

公开榜按账号关联簇、模型 lineage 和平台全局三层限制提交与隐藏晋级次数，近重复
候选共享预算。密封门禁只延迟返回通过/失败或预先定义的粗区间，不返回可自适应搜索的
精确逐项分数，并对同一 lineage 的重复比较做统计校正。联邦学习因投毒、隐私、
客户端差异和复现成本暂不进入首期，只作为后续研究项。

## 9. 目标架构

```text
Web / Desktop correction UI
            |
            v
Contribution API -> consent and rights gate -> quarantine
            |                                  |
            v                                  v
Task scheduler -> blind reviewers -> consensus / adjudication
                                            |
                         PostgreSQL metadata + object storage
                                            |
                             frozen manifests + DVC hashes
                                            |
Approved recipe -> isolated runner -> public validation
                                            |
                                MLflow model registry
                                            |
                    sealed gate -> shadow/canary -> production
```

关键边界：

- 在线项目修订、社区贡献和金标准是三个独立对象，不能原地覆盖。
- 任务服务不读取隐藏评测，训练执行器不写生产模型别名。
- 只有发布服务账号能写生产模型别名，且请求必须携带完整门禁证明和当前治理模式所需
  的批准记录；人工账号不能直接修改 `champion`。
- 社区身份库与公开贡献别名分离，导出数据不包含邮箱、IP 或本机路径。
- 桌面端默认本地保存且不发送纠错遥测；上传前展示确切片段、大小、用途、保留期限
  和撤回入口，只有单独授权且权利检查通过的片段才进入贡献服务。
- 所有批准、撤回、数据冻结、实验运行和模型晋级写入不可删改的审计日志。

### 9.1 当前实现基线

仓库已提供覆盖 C0-C6 的本地可运行控制面，入口为 `/community`：

| 阶段 | 已实现首版 | 仍需生产化 |
| --- | --- | --- |

| C1 | 从已批准审核包生成隐藏校准任务，v2 草稿作为普通社区任务导入。 | 扩充校准集并完成统计置信区间。 |
| C2 | 短音频微任务、答案隔离、分类信誉、账号关联簇去重、共识、所有者裁决与贡献撤回。 | 邀请制真实用户试运行和反滥用压测。 |

## 10. 分阶段任务

以下 C0-C6 是社区能力成熟度，不是整个项目的串行甘特图。C0-C2 约束社区数据进入
可信层，C3 约束社区数据版本发布，C4-C5 约束社区实验和生产晋级；它们不阻塞共享
应用核心、桌面端、离线推理、训练平台或使用其他合法数据的模型研究。

### C0 治理与数据契约

- [ ] 定义贡献条款、音频权利矩阵、隐私告知、撤回与删除流程。
- [ ] 定义 `task_snapshot`、`annotation_submission`、`consensus_label`、
      `dataset_release` 和 `experiment_run` 的版本化 schema。
- [ ] 定义任务类型、初始容差、跳过原因、争议原因和审计事件。
- [ ] 建立角色权限矩阵：单人阶段记录角色兼任与审计，团队阶段强制禁止自审、
      自裁决和自发布。
- [ ] 定义高权限角色的授予、到期、撤销、利益冲突、治理模式切换和紧急回退流程。
- [ ] 实现最小全局撤回清单、历史数据版本阻断、排队任务取消和派生物删除能力。
- [ ] 冻结各任务质量指标的统计口径、最小支持数和置信区间方法。
- [ ] 对训练集、公开验证集和隐藏评测集建立来源及泄漏审计。

退出条件：每个标签、数据版本和模型都能追溯到权利依据与不可变来源；威胁模型和
删除演练通过。

### C1 内部校准与金题

- [ ] 将现有 residual-onset v1/v2 审核包转换为不可变任务快照。
- [ ] 使用已完成的 v1、公开可靠标签和少量抽样专家复核建立首批校准题；不要求
      项目所有者先完成整个 v2 队列。
- [ ] 将未完成的 v2 队列保留为待分发任务，不能将预填参考事件直接当作确认标签。
- [ ] 迁移旧审核记录时重新核验许可与全部内容哈希，标记为 `legacy_verified`；
      项目所有者或后续专家按新 schema 重新签名后才能转为校准金题或训练数据。
- [ ] 从已批准结果制作覆盖音质、漏音、误报和时间边界的隐藏金题。
- [ ] 用至少两名独立复核者测量任务说明、时间容差和人际一致率。
- [ ] 根据争议案例修改指南和 UI，不通过修改答案来提高一致率。

退出条件分两级：首批邀请试运行只需覆盖各基础任务的最小校准集；自动信誉和规模化
分发启用前，再累计至少 `300` 个所有者或专家确认事件并达到本路线图质量指标。该
退出条件不阻塞 C2 界面和后端开发。

### C2 社区复核 Beta

- [ ] 增加账号、教程、任务类型校准、贡献记录和退出机制。
- [ ] 上线数秒级基础任务、盲双审、争议第三审和随机金题。
- [ ] 实现按任务类型的信誉、限流、异常检测和自动暂停。
- [ ] 提供贡献者个人质量反馈、贡献历史和纠错申诉。
- [ ] 仅向邀请测试者开放，先验证数据质量和任务可理解性。

退出条件：至少 `20` 名独立贡献者完成试点；每类核心基础任务至少产生 `500` 个
重叠判断；专家抽检错误率不高于 `2%`。

### C3 公开贡献与数据发布

- [ ] 对所有注册用户开放基础任务，校准后逐类解锁高级任务。
- [ ] 上线主动学习队列，同时保留随机覆盖和长尾配额。
- [ ] 实现共识、专家裁决、任务退休、用户自助撤回和重新开放。
- [ ] 生成版本化训练快照、数据卡、许可清单和覆盖报告。
- [ ] 使用 DVC 管理清单与流水线哈希，音频继续存放在受控对象存储。

退出条件：社区数据可以重复导出，相同版本得到相同清单；训练、公开验证和密封测试
在演奏者、作品、录音、会话和派生链维度均不存在泄漏。

### C4 受控社区训练 Beta

- [x] 实现批准配方目录及带机器认证的 claim/lease/heartbeat/result 调度协议；
      租约过期自动重排，来源撤回立即取消运行任务。
- [x] 实现 macOS 本地无网络沙箱执行器，固定命令映射，不接收任意代码、镜像、
      Notebook、依赖或 shell；已用合成数据完成一次真实训练、上传和回传闭环。
- [ ] 将生产执行器部署到 rootless Podman，并接入 GPU 资源限制。
- [x] 实现每账号并发和每日实验配额、最多三次尝试及失败重排；后续再增加 GPU
      时长预估。资源校验只判断配额、
      配方兼容性和输入规模，不授予额外数据权限。
- [ ] 接入 MLflow Tracking 与 Model Registry。
- [x] 建立真实可执行的合成 smoke、GuitarSet 弦品起音网络和社区快照审计配方；
      Activity Head 在执行规范完整前保持 `planned`，不可提交。
- [x] 自动生成实验摘要、执行证据和模型卡；公开验证榜与详细错误分析仍待完善。
- [x] 支持失败恢复、耗时/内存记录、服务端制品哈希校验和同谱系重复运行。

退出条件：任一用户可在不接触服务器 shell 和受限原始数据的情况下提交实验；平台
可独立重现结果，全部运行具有完整谱系。

C4 的执行器、配方、DVC 和 MLflow 基础设施可以与 C0-C3 并行建设，并先使用现有
公开或已冻结数据验收。只有实验选择社区贡献数据时，才要求相应 C3 快照已经冻结。

本地闭环验收已实际执行两次：

- 合成 smoke 在无网络 `sandbox-exec` 中完成训练、租约心跳、约 `11.9 MB` 制品
  上传、服务端 SHA-256 复算与结果登记；smoke 配方被强制标记为不可晋级。
- GuitarSet 一轮训练和 player-04 三域 validation 总耗时约 `138 s`，峰值内存约
  `1087 MB`。候选公开 TAB F1 为 `0.0378`，明显低于冻结 v5 基线 `0.7042`；
  重复起音召回下降 `0.6876`，Public Gate 自动将其拒绝。该运行只验证基础设施，
  不构成新模型候选，也未访问 player-05 legacy test 或未来密封集。

### C5 隐藏晋级与灰度发布

- [ ] 部署不少于 100 首全新歌曲的物理隔离密封集；执行服务、最小样本校验、固定
      Production gate v2、证据哈希和仅返回通过/失败的接口已实现。
- [x] 建立独立 Public Gate 与 SealedGate 服务身份；维护者不能手工写入谱系、
      复现、公开验证、密封评测和稳健性自动门禁，Public Gate 也无权写密封结果。
- [x] 自动检查同谱系复现、player-04 validation 三域无回退、重复召回增益、耗时
      和内存证据；绝不读取 player-05 legacy test 或未来密封集。
- [x] 实现 `candidate`、`shadow`、`canary`、`champion`、`retired` 模型别名。
- [ ] 建立影子推理、灰度比例、错误预算、告警和一键回滚。
- [x] 提供版本化模型卡 API，披露训练清单、谱系、制品、指标、门禁和已知限制。

退出条件：社区候选无法绕过门禁或自行发布；生产切换和回滚均有完整审计证据。

### C6 扩展与长期运营

- [ ] 将任务扩展到弦品、和弦、技法和易弹编配偏好，但保持独立质量门槛。
- [ ] 建立周期性挑战、数据缺口榜和非金钱贡献认可。
- [ ] 经安全验证后评估受审查的自定义训练代码。
- [ ] 按季度复核指南、金题、信誉漂移、群体偏差和数据许可。
- [ ] 仅在集中式流程成熟后研究联邦学习或端侧隐私训练。

退出条件：标注与训练不依赖单个维护者持续在线，且质量、成本、权利和发布风险均有
可观测指标和替代负责人。

## 11. 当前并行工作流

### A. 产品与桌面工程

立即推进共享应用核心、Electron、离线 sidecar、模型包和项目存储。该工作流不读取
社区标签，因此不等待任何人工复核。

### B. 模型与训练工程

继续使用已有合法标注、公开数据、合成数据和弱监督训练研究候选；并行建设 DVC、
MLflow、受控训练执行器和全新密封评测。未复核数据只能作为弱标签或候选，不能伪装
成确认标签。

### C. 社区任务系统

先开发 C0 的数据契约和 C2 所需的微任务能力，以现有 v1 和少量抽样结果制作最小校准
集。系统可用后再把 residual-onset-v2 批量交给社区，不要求项目所有者现在逐条完成。

### D. 异步人工复核

人工复核持续在后台积累。某一批达到共识和质量门槛时，单独冻结为 C3 数据版本；后续
实验可选择新版本，但正在进行的其他开发和不依赖该版本的训练不暂停。

人工环节只在以下边界阻塞：

1. 未复核标签升级为 `owner_verified` 或 `adjudicated_gold`。
2. 包含这些标签的特定 C3 数据版本冻结。
3. 依赖该数据版本的候选进入密封评测并切换默认模型。

除此之外，产品、桌面、离线推理、训练平台、自动数据管线和其他数据上的模型实验均
继续推进。

## 12. 明确不做

- 不公开现有内部管理审核页面或管理接口。
- 不把点赞、下载量或单一排行榜分数当作标签或模型质量。
- 不让模型预填结果通过多人重复确认后自动变成金标准。
- 不把用户无权再分发的歌曲片段交给社区复核。
- 不让训练任务访问公网、平台密钥、隐藏测试标签或生产存储。
- 不把社区数据自动接入在线训练并自动替换生产模型。
- 不在集中式数据与模型治理成熟前实施联邦学习。
