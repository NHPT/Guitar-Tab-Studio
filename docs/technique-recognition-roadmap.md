# 吉他技法精准识别实施计划

## 目标

将当前“声学特征 + 音符关系”的实验性建议，升级为可量化、可校准、可人工复核的
逐音符技法识别系统。输出必须包含技法类别、起止时间、关联音符和置信度；低置信度
结果只进入待确认状态，不直接写成确定谱面。

## 当前基线

- [x] Demucs 分离吉他声部，低能量时明确回退到原始混音并给出警告。
- [x] Basic Pitch 提取音符起止、音高和力度。
- [x] 指板映射输出弦、品和移动成本。
- [x] 提取 onset、频谱质心、频谱平坦度和过零率。
- [x] 用同弦音高变化推断击弦、勾弦和滑弦。
- [x] 为泛音、拍弦、闷音、切音和轮指提供实验性规则。
- [x] 前端明确标记“技法为实验性建议”，支持逐音符人工校对。
- [x] Worker v8 输出转录模型与技法模型版本、前三候选、独立置信度和声学证据。
- [x] 节拍估计改用起音强度包络，避免低能量鼓分轨造成倍速或错速 BPM。
- [x] 对相邻拍点做限幅局部平滑，消除分析帧量化造成的节拍锯齿。
- [x] 4/4 TAB 按真实起音分组绘制符干、连梁与休止，并对临近拍点做保守量化。
- [x] 修正物理弦序到上下扫方向的反向映射，并收紧普通重复拨弦的轮指判定。
- [x] 记录真实拍点网格和首个强起音，录音前导空白不再写成谱内休止。
- [x] 分离播放时间与 `notationAt`，谱面横坐标对齐原始混音的真实起音峰。
- [x] 时间轴按 SVG 内实际演奏区间滚动，首音不再被弦名与拍号留白推迟。
- [x] 谱面改用亚像素合成层位移与独立单调时钟，并在下一小节起点连续插值，
      消除媒体时间离散采样和小节边界造成的周期性滚动跳步。
- [x] 合并短弱前导与紧邻同音主事件，减少 Basic Pitch 碎片造成的伪拨弦。
- [x] 支持 `source-score-reference-v1` 来源谱校正，并在校谱器中显示来源。
- [x] 击弦、勾弦和滑弦关联到来源音符，TAB 按真实事件时间绘制连接符。
- [x] `legato-optimizer-v1` 用弱起音与时间连续性反向约束同弦指板位置。
- [x] 跨小节击弦、勾弦和滑弦在下一小节绘制延续连接符。
- [x] 校谱器分别展示音符置信度与技法置信度，并保留人工修订来源。
- [x] 同起音音符组使用全局弦品优化，避免多音抢弦并输出位置置信度。
- [x] 自然/人工泛音按实际发声音程映射触弦品，TAB 显示 `<7>` 或 `4<16>`。

当前基线不能作为“精准识别”发布。规则测试只证明分支逻辑正确，不代表真实录音
上的识别准确率。

当前 Worker v8 的技法规则版本为 `heuristic-v4`。在真实歌曲回归样本上，增强后的
结果包含 66 个击弦、36 个勾弦、50 个滑弦和 152 个关联事件；这些数字只用于防止
版本退化，不构成准确率结论。

GuitarSet player-05 已经过多轮受控评测并用于误差分析，现仅作为遗留可比基准，
不再承担最终无偏评测。最终发布必须使用后续建立的、不少于 100 首且从未向模型
设计者披露逐条结果的全新密封盲测集。

## 目标标签

第一阶段必须覆盖：

- 普通拨弦、上扫、下扫。
- 击弦、勾弦、上滑、下滑。
- 自然泛音、人工泛音。
- 掌根闷音、切音/死音。
- 拍弦、打板/敲击。
- 琶音、轮扫、轮指。

后续扩展：

- 点弦、推弦、预推弦、释放、揉弦。
- 拨片刮弦、反馈音和其他效果器相关技法。

### 当前选择性技法模型

- `bend` 仅由 v9 神经模型直接门禁输出：测试支持数 `57`，精度 `1.000`，
  F1 `0.787`。
- `harmonic` 与 `palm-mute` 仅在 v9 神经模型和 v10 描述子 SVM 一致时
  输出：测试精度分别为 `1.000` 和 `0.977`。
- `pick`、`pinch-harmonic` 和 `vibrato` 未通过当前独立门禁，统一输出
  `unknown`；其中测试集没有 `pinch-harmonic` 真值，不能据此宣称支持。
- v9、v12 与 v10 的验证集 stacker 在测试集上降至 `0.926` 的泛音精度
  和 `0.880` 的闷音精度，并产生无测试支持类别的误标，已明确拒绝。
- 当前严格 bundle 只可显式启用，默认 Worker 继续使用带警告的
  `heuristic-v4`，不把启发式结果当作准确率结论。

## 下一执行顺序

以下工作流并行推进，不再把人工复核放在开发主链路前面：

1. **模型研究**：继续使用 GuitarSet、SynthTab、已有合法训练集、合成数据和弱监督
   对比 Conformer/CRNN，针对遗留基准错误设计困难采样与序列模型。
2. **工程开发**：提取共享应用核心和 `InferenceProvider`，建立 Electron 开发版，
   依次验证 macOS Apple Silicon 与 Windows x64 离线 sidecar。
3. **社区工具**：实现社区路线图 C0-C2 的任务 schema、权限、微任务界面和共识
   机制，将 residual-onset-v2 迁入任务池，不要求项目所有者现在全量复核。
4. **异步数据积累**：社区逐步处理 residual 起音、弦品和技法；达到一批数据的质量
   门槛后，按 C3 冻结该批版本，后续训练按版本选择使用。
5. **独立评测**：并行扩充不少于 200 条来源谱事件，并建立不少于 100 首、从未参与
   模型设计的最终密封盲测集。

人工复核只阻塞三个动作：候选标签升级为确认标签、依赖该标签的数据版本冻结、模型
切换默认 Worker。它不阻塞其他数据上的训练实验、架构改造、桌面端或离线推理开发。

## 发布原则

- 未达到 T6 门槛前，界面继续使用“实验性建议”。
- 不用演示数据、规则分支测试或单首歌曲结果代替准确率报告。
- 每次模型升级都必须保留旧模型回滚能力和逐类别混淆矩阵。
