# Guitar Tab Studio 产品与平台路线图

## 1. 目标

Guitar Tab Studio 的长期形态不是单一网页，而是共享同一项目格式、推理协议和模型门禁的
多端产品：

- Web：零安装访问、项目同步、社区微任务和受控训练入口。
- Windows：本地文件工作流、桌面快捷键和可选离线推理。
- macOS：本地文件工作流、桌面快捷键和可选离线推理。
- 云端推理：适合低配置设备和统一模型更新。
- 本地推理：适合隐私、离线使用和不上传音频的场景。

准确率仍是当前最高优先级。桌面端可以先完成架构准备和壳层验证，但不得把尚未通过
生产门禁的模型包装成“准确扒谱”正式版。

## 2. 已确定的技术决策

| 领域 | 决策 |
| --- | --- |
| 桌面框架 | 第一版使用 Electron，最大程度复用 React、Node.js 和现有调试工具链。 |
| 前端 | Web 与桌面共用 React/Vite 组件，不维护两套页面。 |
| 应用服务 | 将当前 Express 中的业务逻辑提取为共享应用核心；Web 通过 HTTP，桌面通过受控本地接口调用。 |
| 推理接口 | 定义统一 `InferenceProvider`，至少包含 `cloud` 与 `local` 两种实现。 |
| 推理结果 | 云端与本地都输出同一版本化 `analysis.json` 和项目格式。 |
| 离线 Worker | 将 Python Worker、FFmpeg 和模型索引打包为平台 sidecar，用户无需安装 Python。 |
| 模型分发 | 模型作为独立下载包，不全部塞入桌面安装包；必须有版本、哈希、兼容范围和回滚信息。 |
| 本地存储 | 桌面端使用应用数据目录保存媒体和制品，SQLite 保存项目元数据、任务与模型状态。 |
| 云端存储 | 正式服务使用 PostgreSQL、Redis 和对象存储，不沿用本地 JSON 状态作为生产数据库。 |
| 社区机器学习 | 所有注册用户可提交基础标注和受控实验；共识、金标准、隐藏评测与生产发布分权。 |
| Web 域名 | 由部署环境配置；社区入口保留 `/community`，API 与媒体使用同域路径。 |
| 首发平台 | macOS Apple Silicon 与 Windows x64；其他架构在稳定后评估。 |

暂不选择 Tauri。当前项目已经依赖 Node.js API 和 Python Worker，Electron 的首次改造
成本最低。若安装包体积或内存成为经过测量的主要问题，再评估 Tauri。

## 3. 目标架构

```text
                         Shared React UI
                     /                     \
              Web Browser              Electron Renderer
                    |                         |
               HTTPS API              Electron Main Process
                    |                         |
             Cloud App Core             Local App Core
                    |                         |
          Cloud InferenceProvider    Local InferenceProvider
                    |                         |
        Redis queue + GPU Workers     Signed Python sidecar
                    |                 + FFmpeg + model packs
                    \_________________________/
                               |
                    versioned analysis.json
                               |
                     shared project/revision model
```

### 3.1 共享边界

必须从当前 API 中分离并复用：

- 项目、任务、音符、节拍、分轨和模型元数据类型。
- 媒体来源策略和文件签名校验。
- Worker 输入、进度事件、取消和结果协议。
- 项目版本迁移与向后兼容。
- 模型门禁状态和“实验性结果”标记。

React 页面不得直接依赖 Express 路径或本机物理路径。所有运行环境通过统一客户端接口
访问项目、媒体和推理任务。

### 3.2 桌面进程职责

Electron 主进程负责：

- 文件选择、拖放、系统菜单和全局快捷键。
- 本地项目目录、SQLite、缓存和磁盘配额。
- 启停 Python sidecar，并限制其监听范围和可访问目录。
- 模型包下载、校验、激活、回滚和清理。
- 崩溃恢复、自动更新、日志导出和诊断。
- macOS 签名、公证及 Windows 代码签名。

渲染进程不直接执行 shell 命令，不持有任意文件系统权限，也不直接加载未校验模型。

### 3.3 离线推理包

每个平台的离线组件至少包含：

- Python 运行时或冻结后的 Worker 可执行文件。
- FFmpeg。
- Demucs 分轨模型。
- 默认转录模型及解码配置。
- 许可证、模型清单和 SHA-256。

模型包必须与应用版本解耦。首次安装可以只包含基础播放与编辑能力，由用户显式下载
离线推理包。未安装离线包时，桌面端仍可编辑已有项目，并在用户允许时选择云端推理。

本地 Worker 只读用户选定输入，输出到受控任务目录。默认不上传音频、特征、日志或
修订；任何同步和训练数据贡献都必须单独授权。

### 3.4 社区数据与训练面

在线项目修订、社区贡献、金标准和锁定评测是四类独立对象。普通用户可以处理
起音存在、漏音、误报和时间边界等数秒级任务；音高、弦品和技法按任务类型校准后
逐项解锁。任务使用盲双审或盲三审形成共识，争议进入可信复核或专家裁决。

社区训练首期只允许选择已批准的数据版本、模型配方和有限参数，在无外网的隔离
执行器中运行。公开验证结果用于迭代，隐藏评测、模型晋级和生产别名只由独立门禁
服务控制。完整角色、数据状态、质量指标和实施任务见
[社区标注与开放训练路线图](community-ml-roadmap.md)。

## 4. 实施阶段

P0-P3 与社区路线图不是严格串行阶段。共享应用核心、Electron、离线推理、训练
基础设施和社区任务系统可以并行开发。人工复核只约束相关标签的数据等级、使用该批
数据的训练版本，以及最终模型晋级；不得阻塞不依赖该批标签的工程开发和研究实验。

### P0 转录准确率与数据自动化

- [ ] 引入可合法训练的大规模弦品或音高数据，减少逐音符人工标注。
- [ ] 优先训练 residual-domain 音高与起音前端，再优化弦品和技法。
- [ ] 用主动学习只抽取模型冲突、漏候选和低置信度片段供人工复核。
- [ ] 使用现有合法标注、公开数据、合成数据和弱监督继续模型研究，不等待
      residual-onset-v2 全量人工复核。
- [ ] 将 residual-onset-v2 保留为未来社区任务种子，社区工具可用后再分发。
- [ ] 将共识数据、专家金标准和全新密封评测物理隔离。
- [ ] 建立不少于 100 首、从未参与设计的全新密封盲测集；GuitarSet
      player-05 仅保留为遗留可比基准。

退出条件：出现通过独立 residual 验证的模型候选；未通过前，产品继续明确标记为
实验性扒谱。

### P1 共享应用核心

- [x] 将 API 中的项目类型、媒体校验、任务状态机和 Worker 协议移入
      `@gts/core` 共享模块。
- [x] 定义 `InferenceProvider`、`ProjectRepository` 和 `MediaRepository` 接口，
      并让当前 API 使用 Pipeline 与 JSON 项目仓储适配器。
- [x] 将 Worker `analysis.json` v1-v9 统一解析为 v9，拒绝未来版本；为旧项目增加
      schema v1 迁移和兼容测试。
- [x] 共享请求只传来源描述与不透明媒体标识，前端组件不依赖服务器物理路径。
- [x] 保持现有 Web 流程和测试全部通过。
- [x] React 工作区通过可注入的 `StudioApplication` 访问项目和推理任务，HTTP
      仅作为默认实现；共享核心提供内存项目仓储。
- [x] 补齐 Electron 本地 `StudioApplication` 与 SQLite/文件媒体适配器。

共享边界已由 Web、API 与 Electron 同时使用。退出条件已满足：同一套前端通过
注入 `StudioApplication` 在 HTTP 与桌面本地运行时之间切换。

### P2 Electron 桌面开发版

- [x] 建立 Electron main/preload/renderer 三层结构。
- [x] 复用当前 React 工作台，不复制页面。
- [x] 实现文件打开、拖放、最近项目、快捷键和窗口状态恢复。
- [x] 在开发模式下调用现有本地 Worker。
- [x] 建立 IPC allowlist、context isolation 和最小权限策略。
- [x] 增加 macOS 与 Windows CI 构建烟雾测试。

退出条件：macOS 和 Windows 开发包可以打开本地音频、完成任务并恢复项目。

### P3 可分发离线推理

- [x] 选择 PyInstaller onedir，提供可重复的跨平台构建规格与制品清单脚本。
- [x] 生成 macOS Apple Silicon sidecar，并在 Windows x64 CI 使用同一冻结流程。
- [x] 将 Worker、FFmpeg、许可证和逐文件 SHA-256 写入可审计 sidecar manifest；
      Demucs 与推理权重使用独立模型包。
- [x] 实现模型包 HTTPS 断点下载、声明尺寸上限、SHA-256 校验、版本固定和回滚。
- [x] 实现任务取消、超时、崩溃恢复和低磁盘空间保护。
- [ ] 基准测试 CPU、Apple Silicon MPS 和可用 CUDA 环境。

退出条件：全新系统无需 Python 环境即可离线完成同一测试音频，并与云端结果满足
确定性容差。

### P4 桌面产品化

- [x] 使用 SQLite 管理项目、不可变修订、任务、最近项目和运行模式。
- [x] 支持导入、导出、备份、恢复、诊断导出和缓存清理。
- [ ] 完成 macOS 签名与公证、Windows 代码签名。
- [x] 实现经 HTTPS 发布源检查、用户确认下载和退出安装的自动更新流程；
      项目与模型回滚独立。
- [x] 建立 macOS arm64 / Windows x64 安装、升级和卸载验证矩阵及发布 CI。
- [x] 将键盘操作、响应式布局、屏幕缩放和高 DPI 纳入 E2E 与发布检查清单。

退出条件：安装、升级、推理、编辑、恢复和卸载在两平台均可重复通过。

### P5 云端与本地混合模式

- [x] 用户可按项目选择“云端推理”或“本地离线推理”。
- [x] 显示预计耗时、模型版本、是否上传音频和资源要求。
- [x] 云端与本地项目使用同一不可变修订结构，以父修订检测冲突。
- [x] 项目校订默认保持私有；只有独立贡献流程和权利校验允许数据进入社区池。
- [x] 云端不可用或配置非 HTTPS 时，本地项目编辑与已下载模型继续工作。

退出条件：同一项目可以安全切换推理提供者，结果来源和模型版本始终可追溯。

### P6 社区标注与受控训练

- [x] 对所有注册用户开放无需乐理的基础微任务，按校准结果解锁高级任务。
- [ ] 实现盲审、共识、专家裁决、任务退休、分类信誉和随机质量审计。
- [x] 发布带来源、许可、切分、谱系覆盖和哈希的数据快照与 schema v2 数据卡。
- [ ] 使用 DVC 管理数据清单和流水线版本，使用 MLflow 注册实验与模型。
- [x] 在隔离执行器中开放批准配方，禁止首期执行任意用户代码。
- [x] 建立隐藏晋级、独立复现、影子运行、灰度、错误预算和回滚控制面。

退出条件：标注和研究训练不再依赖单个维护者；任何社区模型都无法绕过隐藏门禁或
自行进入生产。

## 5. 发布门禁

桌面安装包和离线推理分别验收，不能因为界面可运行就宣称离线模型可用。

### 5.1 桌面应用门禁

- [x] Web 核心工作流无回退。
- [ ] macOS 与 Windows 安装、升级和卸载通过。
- [x] 本地文件访问限制在用户授权范围。
- [x] IPC、sidecar、自动更新和模型下载完成最小权限与输入完整性加固。
- [x] 崩溃后项目与任务状态可恢复。

### 5.2 离线推理门禁

- [ ] 使用与云端相同的独立验证集和指标实现。
- [ ] 同版本模型的核心事件结果在允许的浮点容差内一致。
- [x] 无网络时不触发隐式上传或遥测。
- [x] 模型损坏、版本不兼容和磁盘不足时失败关闭并回滚或停用。
- [x] 模型包显式区分研究与生产通道；旧包默认按研究模型处理。

### 5.3 社区机器学习门禁

- [ ] 公开任务中的每个音频都具有训练和向复核者分发的权利依据。
- [ ] 自动共识样本的专家抽检错误率不高于 `2%`。
- [x] 数据版本、代码、参数、环境、评测和模型制品记录完整谱系及内容哈希。
- [x] 训练执行器强制无外网、只读挂载数据并受资源配额限制。
- [x] 社区用户不能读取隐藏评测或直接发布模型；单人阶段由项目所有者完成最终批准，
      团队阶段再强制独立审批。
- [ ] 生产候选通过独立复现、隐藏评测、影子、灰度和回滚演练。

## 6. 当前执行顺序

以下三条工作流并行推进：

1. **产品工程**：立即提取共享应用核心，开发 Electron 壳层和离线推理包，不等待
   人工复核或新模型。
2. **模型工程**：继续使用已有合法数据、自动生成数据和冻结的旧数据版本训练研究
   候选，同时建设 DVC、MLflow、可复现实验和密封评测基础设施。
3. **社区数据**：先实现任务 schema、权限和微任务界面，再把
   residual-onset-v2 迁入社区队列；项目所有者无需现在独自完成全量复核。

依赖关系只在使用边界上生效：

- 未完成复核的样本可以保留为候选或弱标签，但不能冒充已确认标签。
- 只有使用社区标签的正式训练版本需要等待对应 C3 数据快照冻结。
- 只有模型切换默认后端需要等待 Production gate v2、密封评测和发布批准。
- Web、桌面端、离线推理、训练执行器和社区任务系统的开发均不等待这些人工门禁。
